# Source, tool and model contracts

This document owns source authority and required tool behavior. Some bounded local evidence/review procedures exist; provider adapters have local stubbed-transport and embedded-SQL evidence; actual account/model/tokenizer capability remains unverified. The decision register owns implemented status and test outcomes. All external text and returned links are untrusted data. Tool access is restricted to registry entries; model output cannot expand domains, spending, permissions or tool types.

| Tool | Input / output | Policy and verification | Failure / continuation |
| --- | --- | --- | --- |
| Tavily Search | Incident identifiers, publisher/domain allowlist, configured time filters → candidate URL/title/snippet/time metadata | Confirm issuer/domain/jurisdiction; snippets are discovery, not authoritative plan evidence | No automatic provider retry; retain the original paid attempt/hold; keep Check incomplete separate from no hits |
| Tavily Extract | Registered canonical HTTPS URLs → per-URL results/failed_results and extracted text | Validate URL admission before sending; bound response/context; preserve provider provenance limitations | HTTP 200 with a failed URL is partial; missing/extra URL results held; no fabricated completeness |
| Structured feeds | Existing bounded source adapters → snapshots, geometry, source times | Preserve FireAfter geometry/identity/coverage validation and Unknown semantics | Last success with original age; source failure does not imply safe/no hazard |
| Nemotron extraction | Bounded permitted source-local text/metadata and schema → typed claims with source spans | Validate schema/excerpt hashes/entities/times; model confidence alone cannot establish support | Malformed/unsupported output held; no current automatic retry or model escalation |
| Nemotron comparison | Old/new registered versions and source-local claims → changes, contradictions, explanatory draft | Compare issuer/revision/effective context; do not infer causality or physical hazard values | Ambiguous classification becomes reviewer task |
| Dependency verifier | Versions, claims, plan dependency vector → applicability and affected item IDs | Deterministic scope/clock/identity/conflict rules; human-reviewed semantic support where required | All incident approvals blocked while source classification is unresolved; then affected unresolved dependencies remain blocked |
| Constraint checker | User/verified crew/task inputs → feasible assignments/errors | Deterministic capability/time/window checks; no invented safe road routing | Explain infeasibility; preserve previous approved revision |
| Decision commit | Scoped session, expected revisions, command → atomic receipt | Database authorization, current-generation/clock checks, immutable audit and idempotency | Reconcile original identity after uncertain response |

**Provider choice:** call NVIDIA Nemotron through Nebius Token Factory at runtime. Select an account-verified extraction model; evaluate Nano/Super candidates only if actually offered, measuring quality/cost before escalation. Store exact model ID and prompt/schema/config versions. A stronger model is a later measured extension. The current worker does not escalate; ambiguity stays held for human review. Confirm endpoint schema/tool behavior in a real authorized test. App frontend/database may remain on separate hosting.

**Source authority:** prefer primary issuer documents applicable to the exact incident/jurisdiction and interval. Domain allowlisting narrows discovery; it does not prove the page is current, complete, applicable or a revision of another page. Newer publication time alone does not override another issuer. Conflicting notices preserve both and require review. No document can supply missing burn severity through prose unless a separately validated measurement contract exists.

**Crawler boundary:** use fixed verified provider endpoints; never execute a returned/model-selected URL directly. Canonical registered URLs must pass strict HTTPS/host/path rules and reject credentials, IP literals, local/private hostnames and unsupported schemes before provider dispatch. Search results are candidates until admitted to the registry. Tavily performs its own retrieval; the app cannot claim to enforce or attest its hidden DNS/redirect hops. If final issuer/applicability/completeness cannot be established from returned content and reviewed provenance, hold the claim. No app-side arbitrary fetch/browser tool exists in this release. Any later direct-fetch adapter needs its own resolver/redirect/network controls and tests.

**Concrete adapter behavior:** Search uses fixed domain filters and max_results=5; query text is derived from the original operator-reviewed issuer/jurisdiction registry, never arbitrary user/model text, private notes or facility details. Extract uses registered URLs in one batch with full-content settings, no relevance query/chunk sampling, images disabled and bounded timeout. Examine both results and failed_results even for HTTP 200; require exactly accounted requested URLs, reject duplicates/unknown returned URLs, and retain request_id where supplied. Extracted text is the preserved source representation; do not invent original HTML bytes, HTTP status, publication date or complete redirect provenance. The current worker makes one Search and one Extract without transport retries. The four-request SQL ceiling is a reservation cap, not implemented retry behavior. Any later qualified retry must use an explicitly authorized new attempt within the original cumulative budget; an uncertain paid attempt never grants redispatch. [Tavily Extract contract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)

**Temporal policy:** accept only source-supported publication/effective metadata; preserve null when absent. Date filters are retrieval hints. Freshly fetched old content stays old. Rechecking identical content adds a retrieval event, not a new publication date. Withdrawn notices and unresolved material updates change dependency validity immediately.

**Implemented interpretation:** source-local extraction and comparison now have strict draft schemas. Exact quotes yield app-computed UTF-8 offsets; absent or repeated quotes reject. Unique non-uploaded selected-asset names are matched locally from quoted mentions; asset IDs and private notes never enter prompts. Unchanged current-model/prompt records can be reused with original lineage. Machine output remains unreviewed, and only the existing human commands can resolve applicability/materiality or approve a plan. Partial URL results are recorded individually, with actual request identity, and do not count as a complete check.

**Recovery diagnostics:** worker failures use a fixed allowlist of safe stage codes. Capacity, incomplete retrieval/corpus and invalid citations have plain-text recovery explanations; unknown exceptions remain verification_failed and never expose source/provider messages. No failure explanation authorizes retry, truncation, budget renewal or approval.

**Prompt contract:** request task-specific structured outputs and concise evidence-linked rationale. Include source provenance, mode and entity bounds. Tell the model that embedded page instructions are quoted data. The interpreter has no credential/store/decision write tool. Do not request/store private chain-of-thought. User-facing explanations cite externally inspectable evidence.

**Model capability fallback:** account model IDs, JSON/structured-output support and tokenizer behavior remain unverified. Local Nemotron transport uses a qualified-evidence-hash gate and a conservative serialized-message allowance; actual tokenizer/count/usage qualification must precede live model execution. Do not assume function calling or strict JSON schema support. Parse and validate plain JSON output with the app's existing validation conventions; malformed/schema/context-overflow output is held. User review notes and private identifiers are excluded from model input by default. Model/provider fallback cannot change permissions, source policy or usage accounting. [Red-team probes](RED_TEAM_PLAN.md) rerun after any model/prompt/tool change.

**Monitoring:** manual refresh first, then one durable scheduled worker after target/budget/cadence decisions. Proposed source-check cadence 30 minutes with per-source backoff; this is unapproved and no monitor is created by this pack. Stop work at hard ceilings, expose next eligible retry, and bound cumulative attempts/bytes/tokens across restart.

**Native evidence authority:** mode labels alone are insufficient. Fresh default adapters can produce a signed acquisition receipt; cached/custom inputs must retain an existing valid receipt. The stored snapshot must also match a scoped signed binding and a currently valid, unrevoked owner key. Missing configuration or failed verification preserves the source as unbound and blocks its use for approval. Unknown dates remain unknown. Source content and applicability still require their ordinary checks. The [architecture](ARCHITECTURE.md#native-acquisition-and-stored-row-authority) owns the mechanism and [decision register](DECISIONS_AND_BUILD_GATE.md#current-verification-and-coverage) owns its partial qualification.

**Live versus replay:** isolate run mode, storage references and exports. Replay only exposes versions available at simulated time. A synthetic update is explicitly identified as authored fixture content, never presented as an agency notice or used by a live plan dependency. The live path must show real sponsor execution even when no material change occurs.

**Data rights:** retain/reproduce text only as allowed by the source terms. Store link and sufficient licensed evidence where full text cannot be retained. Keep restricted agency uploads private and exclude their content from external model requests unless that data destination is explicitly authorized. Content retention and provider data handling are open decisions.
