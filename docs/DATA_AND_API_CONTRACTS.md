# Data and API contracts

This is the final target contract. The route table distinguishes 26 methods present in local source from future endpoints. Presence in source does not establish full-target verification; claim-list HTTP/helper and embedded-SQL checks are local only. Implementation verification and source snapshots are recorded only in the decision register. Atomic decisions and reconciliation now exist locally; optional feedback capture is integrated locally; history and immutable briefings are implemented locally; the reviewer interface is a locally exercised candidate; complete authenticated/provider acceptance remains pending. Reuse inherited organizations, memberships, incidents, assets, source snapshots, recommendations, responder actions and audit events where their verified contracts fit.

[Architecture](ARCHITECTURE.md) owns table mappings, locking, job protocols and numerical ceilings. This document owns record, endpoint, role and serialization contracts. All inherited records are copied/recreated only in the fresh Sentinel database; no original FireAfter store is reused.

## Shared identity, roles and time

**Native provenance serialization:** SourceSnapshot may carry nativeAcquisition with schemaVersion=1, keyId, organizationId, incidentAlias, mode, contentHash and signature. Stored source_snapshots.raw_payload may carry sentinelNativeBinding with schemaVersion=1, keyId, organizationId, mode, frame and signature, alongside sentinelMode/dataOrigin. These are server-generated records, never caller authority. The frame binds the complete selected stored projection; key values stay out of responses. Missing, altered, cross-scope, expired or revoked binding produces native_mode_unbound in admission. Architecture owns signing, clocks and the private key table. Synthetic local integration checks cover default NWS acquisition, checkpoint/staged row transport, persisted SQL binding and hydrated receipt; they do not establish fresh-target native ingestion acceptance.

**Common envelope:** opaque UUID; organization_id and incident_id on private records; schema_version; created_at from server; originating run/revision when applicable. Validate incident membership for every referenced ID. Use organization/incident composite relationships or equivalent checks to prevent cross-scope joins. App service-role access is not authorization: verify caller membership before each privileged operation.

**Clock contract:** distinguish publication time, effective time, retrieval time and freshness expiry. Store UTC instants plus any source timezone interpretation. Unknown/future/invalid metadata is flagged. Effective future notices cannot masquerade as currently effective evidence. Compute decision_checked_at from the database wall clock after acquiring locks, immediately before validation; transaction-start time is too old after a lock wait. Browser/model clocks are untrusted.

**Role matrix:** use exact inherited roles: incident_commander, analyst, viewer. incident_commander and analyst can run retrieval, review claims, edit constraints, draft/modify proposals and annotate; only incident_commander accepts/rejects a plan. Authorization of the shared decision endpoint is per action, not a blanket deny of every analyst command. Analyst annotation cannot approve it. Viewer reads only authorized projections. Judge is a purpose: provision an isolated demo incident_commander account for decision tests. Anonymous users access only the explicit redacted public projection. No body field grants a role. Recheck current membership in the committing RPC. Inherited requireCurrentUser rejects viewer, so a Sentinel read helper must explicitly validate authenticated viewer membership rather than assuming a roles argument will widen that helper safely.

**Version vectors:** immutable dependency references bind the proposed plan. The incident generation fences concurrent updates. A content hash is integrity evidence and does not establish authority, source identity, semantic support or real-world accuracy.

## Evidence records and human review

**Implemented evidence foundation:** contracts.ts, evidence.ts and store.ts prepare bounded immutable version identities, mechanically validate citations, and read versions through a service-only scoped RPC. Migration 20261011190000_sentinel_evidence_records.sql introduces five evidence/state tables with composite references and immutable-record triggers. publication.ts and migration 20261011210000_sentinel_evidence_publication.sql add a private leased batch command, current document pointers, append-only change markers and publication receipts. Atomic plan decisions have a separate implemented contract below. The decision register owns observed check results. Citation offsets are UTF-8 bytes of the normalized text. UTC serialization supports millisecond precision; unsupported precision remains an input error. Version identity normalizes equivalent UTC representations, never retrieval time. Text retention follows full_text/excerpt_only/metadata_only; valid citations still require independent semantic/applicability review.

**Private claim contract:** claims.ts and migration 20261011230000 implement publishClaims/readClaimPage. A worker supplies the existing scope/run/owner/fence, stable commandId, expectedEvidenceGeneration, 1–5 versionIds, 0–25 strict claim drafts and optional transientTexts keyed by canonical version UUID. Drafts contain ID, version ID, exact UTF-8 excerpt range/text/hash, kind, bounded claimText, incident asset candidate IDs and model/prompt labels. They cannot supply actor, creation time, support or permissions. SQL derives scope/run/creation time and requires current leased authorization, configuration, head identity and generation. It independently verifies the citation and all candidate IDs. Model/prompt labels describe the worker input; they do not prove a real model call. Jurisdiction and effective interval remain inherited from the referenced immutable version.

The immutable command binds generation/version IDs/claim drafts but never transient source text. Receipt binds scope/run/command/fence, database commit time, generation, committed unresolved count, versionIds and ordered claimIds, with semanticSupport=unreviewed. Replay requires current lease/authorization and identical command payload; altered payload conflicts. Citation publication never resolves a marker or enables a dependency. Full-text versions use retained source bytes. Excerpt-only versions require matching transient normalized text, retain at most 2 KiB of unique quote coverage per version across commands, and cannot retain the whole source. Metadata-only sources cannot publish excerpts. Source permission must be independently established; the technical cap does not grant rights. No full transient source may enter checkpoints, SQL bind logging, telemetry or command archives.

Private member pages contain scope, versionId, observedAt, generation, unresolved count, currentEvidence, items with sequence/immutable claim/citationVerified=true/semanticSupport=unreviewed, hasMore and nextAfterSequence. Pages have at most 25 rows and 768 KiB of item JSON; smaller byte-limited pages retain a valid continuation, and the helper rejects serialized results over 1 MiB. The cursor is an internal position, not authority. Current membership is rechecked in SQL; absent scoped versions return null. currentEvidence reports head/config identity only. Claim publication/pages describe extraction only; human review is authoritative in its separate projection below. GET /api/sentinel/documents/:id/claims now binds the member reader to a browser response. It replaces nextAfterSequence with nextCursor: canonical base64url, at most 256 characters, bound to incident/mode/version and validated before read. Current SQL membership remains the authority. Worker-produced classification drafts exist locally; real model qualification, alternate marker-resolution policies and public view remain pending; HTTP/helper and embedded-SQL checks cover the new binding locally; real target/authenticated acceptance remains pending.

**Human claim-review contract:** claim-reviews.ts and migration 20261011231000 implement append-only review and latest member projection. Write input contains incidentId/mode, path claimId, commandId, expectedEvidenceGeneration, nullable expectedReviewId, support (supported/unsupported/unresolved), applicability (applicable/not_applicable/unresolved), provenance (verified/unresolved), conflict (clear/unresolved) and optional note (2,000 characters/8,000 UTF-8 bytes; valid Unicode/no NUL). Actor, organization, IDs, role, receipt and time cannot come from the browser. Current analyst/commander membership, source identity and asset candidates are revalidated in SQL. New review increments generation; it neither resolves a marker nor approves a plan, and reopens previously resolved markers covering that version when necessary. The expected revision is the latest stored review ID, null for the first review. Every exact same-key replay is a historical result under current authorization; conflicting payload rejects. Receipt binds review/claim/actor/scope/command/previous review/time/generation and committed unresolved count, including any reopened source markers. Latest read includes scoped claim/version, observed time, generation/unresolved count, currentEvidence and paired nullable review/receipt. Current head identity does not establish freshness or applicability at plan commit. Optional typed feedback is appended by the review wrapper in the same transaction; unsupported fields reject. Feedback does not change the human judgments or immutable original claim.

**Comparison draft contract:** changes.ts and migration 20261011232000 implement private publishChanges and member readChangePage. Worker input contains scope/run/owner/fence/commandId/expectedEvidenceGeneration and 1–5 unique marker-bound drafts. Each draft contains ID, markerId, category, materiality, up to 25 unique claimIds, up to ten unique affectedEntityIds, bounded explanation, modelVersion and promptVersion. Actor, old/new version IDs, source document, creation time, approval and stage cannot be supplied. SQL stamps scope/run/document/old/new/time and literal semanticAccepted=false/stage=draft, checks current lease/config/generation, cited exact version-pair membership, current assets and citation-backed entity candidates. No source marker closes. New draft/claim publication reopens affected resolved markers atomically; an optional positive reopenedMarkers field accompanies a single generation increment for the batch. Zero-claim publication cannot report reopening. Replay retains the original receipt and does not reopen again. Citation integrity and model labels do not prove meaning or provider execution. Empty citations require unresolved materiality except a metadata-verified withdrawal. Different authorities cannot be benign/substantive supersession.

The immutable receipt binds scope/run/command/fence/time/committed generation and unresolved count plus ordered changeIds/markerIds, always semanticAccepted=false. Identical command replay is historical under current lease/authorization; changed payload conflicts. Member pages retain all draft history with isLatestDraft/currentEvidence, classificationPendingMarkers and unresolvedSourceChanges separately. At most 25 items/768 KiB item JSON, under the 1 MiB envelope limit; shorter bounded pages retain a continuation. SQL rechecks current membership and coherent incident generation. HTTP exposes nextCursor in place of internal nextAfterSequence; it is incident/mode-bound canonical base64url, at most 256 characters, not authority. Unsupported filters reject. A zero-row page never asserts no changes or accepted evidence.

**Human source-marker review:** marker-reviews.ts and migration 20261011233000 implement private source preview and human hold/resolve. Input: incidentId/mode, path markerId, commandId, expectedEvidenceGeneration, nullable expectedReviewId/changeId, expectedReviewVectorHash, action (resolve/hold), materiality (material/benign/unresolved), completeReview, provenance (verified/unresolved) and mandatory bounded note. Material resolve requires a supported applicable current-version claim; no missing/uncertain claim review is silently discarded. Human whole-source/provenance attestations are not automated semantic proof. Current full-text eligibility alone does not approve tasks or establish source freshness.

Preview returns scope/marker/document/version metadata, generation/unresolved count, opaque reviewVectorHash, unresolvedClaimReviews/supportedCurrentClaims, resolutionIssues, latest comparison/review IDs, derived resolved/reason and paired nullable immutable human review/receipt. It omits source text and the retained claim-review vector. Issues include stale current source, unavailable/full-text/authority/extraction/claim-review/vector-capacity problems and changed entity candidates. Resolve/hold stores the full bounded claim-review vector and advances generation once. Counter changes occur only when actual marker resolution state changes. New cited claims, claim judgments and comparison drafts reopen affected markers once, retaining invalidations and historical human receipts. A replayed resolved receipt is history; read the current preview for current state. Historical/supersession and restricted/withdrawn/quarantined-source coverage policies remain pending; unresolved conditions retain the fence.

## Source publication and configuration

**Private publication contract:** SourceConfiguration is schemaVersion=1 plus one to five unique sources, each with documentId, documentKey, canonicalUrl, issuer, jurisdiction and contentPermission. An observed result carries a prepared version; failed/incomplete acquisition carries only safe error and retrieval metadata. Initial publication and later relevant changes conservatively fence incident approvals pending classification. Rechecking the current identity creates only an event. Returning to an earlier identity reuses its immutable version and records a new transition. Failed acquisition retains the last pointer and original age. Same-command replay returns the original receipt under a current authorized lease; changed payload conflicts. Lease/deadline are checked again before commit. Restricted-permission versions and command payloads retain no full text. No browser worker-publication or source-activation endpoint exists; human source-marker review is separate below.

**Private source configuration/read contract:** sources.ts and migration 20261011220000 implement activateSourceConfiguration, readEvidenceSummary and readSourceChangePage. Canonical UUID/URL serialization and a shared versioned compact-array SHA-256 bind the registry; source order is retained. Identical configuration is a no-op; exact replay returns the historical receipt under current authorization; changed payload or stale expectation conflicts. Changed configuration fences old runs and preserves reservations/history. Operators cannot change stable document ID/key bindings or self-admit through runtime grants.

Member summary includes the active registry/hash/revision, generation, unresolved count, observation time, version metadata and latest active-config retrieval outcome. No check and failed check remain distinct; a retained old-config head is labeled matchesConfiguration=false. Source-change pages are private low-level transitions, not semantically accepted changes: 25 rows, increasing evidence generation, hasMore and an internal nextAfterGeneration. ## Worker dispatch and recovery

**Private worker records:** DispatchAttempt binds immutable attempt UUID, logical run/scope, sequence1–4 and server time. DispatchReceipt binds that attempt to one scheduler runtime ID and acknowledgment time. WorkerOutput binds run/scope, contiguous sequence0–20, kind(context/search/extract/evidence/claims/changes), exact frame, parsed payload, SHA256, creator fence and server time; raw runtime table access is revoked. These records never enter viewer responses or Workflow history. Actual completion requires current registered-head/extraction coverage and changed-marker publication, independent of a saved output label.

**Dispatch response:** dispatchPending=true reports an unconfirmed scheduler start after durable admission; it is not rollback. Retry the original command/body, preserving its UUID and run deadline. No private worker output, scheduler credentials or raw source text enter this response. A confirmed queue is not completed retrieval or plan approval.

**Implemented durable-run foundation:** runs.ts and migration 20261011200000_sentinel_run_admission.sql add five execution tables plus private admission/read/cancel, lease acquisition/renewal, reservation/settlement and checkpoint RPCs. Admission and cancellation persist scoped actor/command receipts atomically. The three run HTTP routes enforce origin, body size, safe errors and private/no-store responses. Read allows an authenticated viewer; cancel requires the creator or a current incident_commander. Worker identity comes from the stored run and is reauthorized in SQL. Replayed admission does not renew the deadline; replayed reservation never permits redispatch. Reserved request/token counters remain charged even after settlement; uncertain attempts occupy organization slots through their dispatch deadline, including after cancellation. Checkpoints cannot publish ready/completed results. Owner-priced money/unit reservations and server-only provider transports are now implemented locally. Manual Workflow dispatch/reconciliation and the source-to-draft pipeline now exist locally; actual scheduler, tokenizer and real provider/account qualification remain pending. A queued run is not a completed check or an admitted paid call.

## Decisions, delivery and errors

**Implemented decision contract:** the path supplies planRevisionId; bodies cannot supply it, actor/organization, IDs, timestamps, outcome or evidence snapshots. Bodies require incidentId/mode, commandId, expectedPlanRevision, expectedEvidenceGeneration/vector, expectedConstraintRevision, nullable expectedPolicyRevision, action, note (2 KiB UTF-8, valid text) and modifications (null except modify). Modifications contain 1–10 unique task/crew/start assignments and must cover every selected task under current constraints; the server/SQL creates a new draft with retained dependencies/policy. Selected-task or estimate changes use constraints/new-proposal commands. Optional typed feedback is integrated atomically with the existing review/decision receipt; unsupported feedback fields reject. Operational review and owner-permissioned offline reuse remain separate.

Decision binds IDs for receipt/audit, plan/reviewed revision/nullable new revision, actor/action/note, reviewed generation/vector, constraint/policy, initial checkedAt, record committedAt and timeBasis. Receipt binds scope/actor/command/decision/audit/reviewed/new revision, reviewed generation/vector, action and initial timestamps. For accept only, finalValidation binds kind=final_admission, decision/revision/vector, last checkedAt/timeBasis and eligible=true; other actions return null. All three are checked for exact consistency. A confirmed receipt attests a human plan decision, not physical execution; validity may expire after the recorded check. SQL retains the decision-time snapshot and separate immutable audits/terminal status. Projection current validity never rewrites a past approval.

Expected version fields bind the reviewed immutable proposal. Accept additionally requires current evidence/policy/constraints and eligible admission at both checks. Reject only requires the current proposal, so an expired/infeasible proposal can be rejected. Annotation may retain a historical revision; modification needs the current unchanged evidence/constraint/policy snapshot. Current role is rechecked even on replay. Late persistence/admission failures roll back the decision, audits, terminal/approved pointers and any new modified draft. DECISION_CONFLICT includes stale/competing commands and deadlock aborts; map auth/scope/input/conflict/unavailable to 401/403/400/409/503. No private database diagnostic is returned.

**Successful decision example:** request supplies expected version fields and action=accept; actor identity comes from the session. Response includes decisionId, receiptId, reviewedPlanRevision, reviewedEvidenceGeneration, committedAt and replayed. The response never claims execution of physical inspection tasks.

**Delivery semantics:** a server receipt attests a complete serialized artifact of the declared revision/hash, not a completed client download. The client buffers the bounded response and verifies exact length/hash before offering a saved blob. Interrupted/mismatched delivery has no client success state. Browser print/PDF has no trustworthy automatic disk-save confirmation. Historical briefings retain decision-time evidence and separately label current validity; fresh retrieval cannot rewrite the original briefing.

**Implemented run error contract:** JSON contains a safe error string and, for typed run failures, code. AUTH_REQUIRED maps to 401, SCOPE_DENIED to 403, INPUT_INVALID to 400, RUN_CONFLICT/RUN_BUSY to 409, BUDGET_STOPPED to 429 and STORAGE_UNAVAILABLE to 503. An unavailable scoped read returns 404. Origin/body/media rejection uses 403/413/415 and does not always include code. Every response is private/no-store. traceId and retryable fields are not currently emitted; clients cannot depend on them.

**Implemented evidence read HTTP contract:** handled GET responses have private/no-store, Vary: Cookie, JSON content type and nosniff; serialized responses are bounded to 1 MiB. Strict query parsing rejects duplicate, missing or unknown keys before any reader call. Summary/version reads reject cursor; source-transition reads validate canonical cursor encoding, positive safe-integer position and exact incident/mode binding. UUID inputs are normalized to lower case before database identity comparison. Source/read errors map AUTH_REQUIRED=401, SCOPE_DENIED=403, INPUT_INVALID=400, SOURCE_CONFLICT=409 and STORAGE_UNAVAILABLE=503; unexpected exceptions are redacted. Absent scoped reads use the same generic 404 body. These are authenticated private endpoints, not public redacted views or proof of source meaning.

**Proposed remaining error envelope:** code, message, traceId, retryable, optional conflict summary. Additional planned codes: SOURCE_UNAVAILABLE, EVIDENCE_AMBIGUOUS, CLAIM_UNSUPPORTED, RUN_CANCELED, PLAN_INFEASIBLE, PLAN_STALE, COMMAND_CONFLICT, DELIVERY_INCOMPLETE. Introduce the envelope through a compatible versioned contract rather than documenting it as current behavior. No credentials, provider stack traces or sensitive coordinates in public errors. Rows marked Implemented local identify methods present in source; all other rows specify future endpoints. The validator compares the table with actual route exports. Presence does not imply qualification; the decision register owns current results, original failures and remaining acceptance. Briefings and optional feedback are local implementations with full-target acceptance pending.

**Bounds:** [architecture](ARCHITECTURE.md) owns runtime ceilings and their qualification limits. Product limits come from [supported scope](PRODUCT_REQUIREMENTS.md); request/token/body/transport limits come from architecture. Limits include all retries and cannot be overridden through request fields. Overflow stays explicitly incomplete or rejected.

**Migrations:** additive tables/indexes/policies and atomic command functions on disposable test resources first. Verify grants, cross-organization/cross-incident references, RLS where used, service-role RPC restrictions, append-only records, generation locking and recovery. Static migration-contract checks do not demonstrate applied hosted controls. Apply inherited migration order deliberately; never bulk-run old scripts against FireAfter production.

## Optional typed reviewer feedback

Optional FeedbackObservation is implemented locally in migration 20261012004000_sentinel_feedback.sql and appended atomically with its existing claim-review or plan-review receipt. Fields: opaque id; organization/incident; claim_id and immutable claim/source version; originating run/model/prompt/policy revision; original_claim_hash; corrected_claim_text or corrected_claim_id; reason_code; review_kind (claim or plan), exactly one claim_review_id or review_decision_id, and receipt_id; server-derived actor/time; permission_record_id if present. Bounded correction text: 2 KiB UTF-8. Supported reasons: identity_error, time_error, unsupported_claim, constraint_error, not_material, other. Do not require prose on every accept or create a new feedback screen. Notes remain optional operational context, not model instructions.

The optional feedback input uses schemaVersion=1, claimId, originalClaimHash, exactly one non-null correctedClaimText or correctedClaimId, reasonCode and nullable permissionRecordId. originalClaimHash is SHA-256 of the exact UTF-8 immutable claimText, not the source document or the whole JSON object. The server derives source/version/run/model/prompt/policy and original review/receipt references. Corrected claim references must use the same scoped immutable source version; plan feedback must reference a dependency of the reviewed revision. Feedback is a sibling of the immutable review/decision and receipt in responses, not a rewritten decision body. Inputs without feedback retain the existing response shape.

Integrate feedback into the existing scoped review endpoint and command key. A feedback payload cannot mutate the immutable original claim or decision, alter a role/policy, fetch a URL or dispatch a provider request. Unsupported/oversized/cross-scope payloads reject before transaction commit. Same-key replay returns the same receipt and signal ID; contradictory replay conflicts. The selected claim/plan review reference and receipt belong to the same committed scoped operation. ReviewDecision may reference feedback_observation_id. Signal IDs use scoped relationships; deletion/redaction policy follows the owner's approved retention rules without rewriting the original decision rationale.

## Operational authority and learning permission

Operational processing authority must already be established before private data use. Owner-provisioned PermissionRecord identifies data_owner_id and grantee_actor_id, exact purpose offline_internal_evaluation, organization/incident/mode, destination sentinel_internal_evaluation, grant/expiry/revocation time, retention_policy_revision and authority_evidence_hash. Only the database owner can provision grants after checking actual data-owner authority; runtime roles cannot enroll or broaden them. Grant fields are immutable; the owner may set the first nonfuture revocation, which cannot be cleared. These technical records do not establish the unresolved human processing/retention policy. A checkbox from an arbitrary user is insufficient authority. Absent, revoked or mismatched permission excludes the record from learning extraction. No shared public or cross-agency dataset is created; no provider upload occurs by this feedback path. The private readFeedbackForEvaluation helper admits only a current commander who is the grant grantee, matching destination/retention revision and a currently effective unrevoked grant, using the post-lock database clock. It returns null for absent, expired, revoked or mismatched grants and performs no provider upload, training or policy promotion. Ordinary review/history remains available after revocation. Private source text/corrections are absent from normal telemetry, sponsor feedback, public repository/video and unauthorized exports.

For the hackathon, use synthetic/authorized public demonstrations; do not collect real private corrections before the data-owner policy is resolved. Judge reproduction and the whole workflow work without learning permission or a proprietary corpus. Permission denial does not remove normal review/briefing functionality. Explicit retention/legal records requirements remain a human decision, not a promise to erase all historical audit facts automatically.

## Portable briefing lineage

The specified bounded JSON briefing must include plan/parent revision identity; exact evidence vector/generation; relevant document/claim hashes, provenance/version references and permitted cited excerpts; dependency links; declared constraints/policy version; mode/timestamps; actor/decision/receipt; later current-validity projection labeled separately. Verify the structure using a self-contained, redacted example fixture without private assets. Exclude secrets, unrelated/private records and learning permission records. When content cannot legally be bundled, include its permitted reference/hash and a visible unbundled-content limitation; do not promise an independent full-source reconstruction from a URL alone.

Printable HTML and JSON retain their existing 2 MiB limit, authorization and complete-client-byte/hash checks. If the complete permitted revision cannot fit, reject with an explicit capacity error; never silently omit dependencies. An importer or third-party export format is not part of this release. Complete open JSON preserves customer portability; no deliberate data hostage mechanism is a moat.

A briefing is immutable once serialized. If a later request includes a newer current-validity projection, create a distinct immutable artifact/hash with that projection and its observation time; preserve the previous artifact and original decision-time snapshot. Never overwrite retained bytes or relabel an old projection as currently checked. Hash/byte verification always applies to the exact full serialized response.
